CATEGORIES DELETE HTTP 403 - FIX COMPLETE
================================================================================

ISSUE:
------
Category DELETE operation returned HTTP 403 (Forbidden) while CREATE, READ, and
UPDATE were working correctly.

ROOT CAUSE:
-----------
Two conflicting RLS UPDATE policies on the categories table:
  
  1. Migration 20260913 created: categories_update_delete_own_tenant
     - Missing: deleted_at IS NULL check
     
  2. Migration 20260915 created: categories_update_tenant  
     - Has: deleted_at IS NULL check
     
When both policies exist, PostgreSQL RLS evaluation fails with 403 because
conflicting requirements can't be satisfied simultaneously.

THE FIX:
--------
Removed RLS policy CREATE statements from migration 20260913. Now only 
migration 20260915 creates the correct policies, ensuring single source of 
truth and eliminating conflicts.

File Changed: supabase/migrations/20260913000001_upgrade_categories_module.sql
Removed: 20 lines (RLS policy CREATE statements)
Kept: Column additions, indexes, views, functions, triggers
